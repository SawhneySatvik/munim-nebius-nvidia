Causes, in order of reach:
1. **Blind specialist choice** (net sales, labour). Before `load_skill`, nothing tells the Manager which specialist holds which
   read, its arguments or its columns.
2. **Dates computed by the model** (labour, payout). No date window is in the context, so Nemotron guesses: one day, or a month
   that starts on the business date.
3. **No outlet handle** (expiry, payout, labour on Super VL). An outlet named in the question cannot be passed, so the model
   borrows `outlet_id` handles from unrelated reads, or types a name or "None".
4. **Time.** Ultra thinks 5 to 25 s a step against the 80 s ask budget, so each wasted read risks the time limit.
5. **The finish tool counts against the tool cap** (labour on Super VL). Once 10 tool calls are used (parallel reads use them
   fast), `submit_answer` itself is refused, and the run can only end "cannot verify".
6. **A gap that is not intel's.** No template and no run-frame field names a delivery channel, so "Swiggy" cannot be tied to a
   cell: `channel_id` cells carry no name, and `finance.pnl` by channel keys on the id.

Found while fixing (each measured live; the run ids are in §5):
7. **The first submission types numbers.** Nemotron writes dates, "two batches", "the next three days", "30%" and `(O1)` into
   its prose. The grammar refuses them correctly. But the refusal named only the first rule of the first bad segment, so the
   one allowed retry fixed that and kept the rest, and the answer abstained.
8. **"none" for null.** Nemotron writes the string `"none"` / `"None"` for a null outlet, channel, channel kind and abstain
   code. A channel kind of "none" silently filtered a read to 0 rows.
9. **NVIDIA endpoint 429 bursts.** With the fixes, Ultra steps take 1 to 3 s, and four of them in a row draw `429 Too Many
   Requests` for about 3 s. The OpenAI SDK's default 2 retries give up inside 2 s: 8 of 11 stack asks abstained on it,
   every one with a `RateLimitError` trace.
10. **The run's input-token cap (100k).** Shown on every call, the read index (about 2.5k tokens) pushed one long payout ask
    over the cap at step 6.
