# ADR-004 · Transactional outbox, publish-after-commit, scheduled sweeper

**Status:** accepted (9 Oct 2026; revised after pass-1 review) · **Ledger:** R1, R10, R20

**Context.** intel must see every business event at least once without dual writes. Request-billed Cloud Run throttles CPU outside requests, so a polling relay service stalls (R4 K5, pass-1 review).

**Decision.** Each command writes outbox rows in its transaction (Debezium-compatible columns). After commit, the same core-api request publishes them to Pub/Sub `munim-events` and sets `published_at`. A Cloud Scheduler-triggered `core-worker` job (`outbox-sweep`, every minute) claims rows unpublished for > 30 s via `core.outbox_claim(batch)` (SECURITY DEFINER, EXECUTE to `munim_svc` only) and publishes them. Push subscription to intel `/events` (OIDC, ack 300 s), DLQ after 5 attempts, drained by a `dlq-drain` job into an operator alert. Event types `munim.<module>.<entity>.<past-tense-verb>.v<N>`.

**Consequences.** Consumers dedupe via `events:claim`. Moving to CDC later is a configuration change.
