# ADR-005 · Realtime by SSE from Postgres LISTEN/NOTIFY

**Status:** accepted (9 Oct 2026; revised after pass-1 review) · **Ledger:** R20 (amends R9)

**Context.** Pub/Sub subscribers stall on request-billed Cloud Run (R4 K5). Browser `EventSource` cannot send auth headers or reconnect with a fresh credential.

**Decision.** Three channels, ids only: `munim_outbox` (`<tenant>:<outbox_id>`, replay from `core.outbox`), `munim_trace` (`<tenant>:<run>:<seq>`, replay from `intel.trace_event`), `munim_inbox` (`<tenant>:<id>`, replay from drafts/findings by `updated_at`). Each core-api instance holds one LISTEN connection and fans out after re-reading under RLS. Browsers use fetch-based SSE (a `ReadableStream` reader in `packages/sdk`) so the member token rides in the `Authorization` header and `Last-Event-ID` is sent on every reconnect; topics are authorised per request. Cloud Run `--timeout=3600`; clients reconnect at 55 min with `Last-Event-ID`.

**Consequences.** Traces and findings never ride the outbox (they would loop back to intel). Any role can `NOTIFY`; spoofed notifications are harmless because handlers re-read under RLS.
