# ADR-007 · ADK Manager + specialist skills + read-only branch Runners; per-request sessions; recorded model in tests

**Status:** accepted 9 Oct 2026 (revised after the pass-1 review). **Amended 11 Oct 2026 by ADR-014 (ledger R45, addenda F5 and F8).**

**Ledger:** R8, R25, R36, R45.

**Context.** Eight packs, and cost per outlet matters (R3). The back office must show what really ran. intel may not write Postgres (R25), and `DatabaseSessionService` creates and writes its own tables.

> **Superseded (11 Oct 2026, R45/ADR-014)**: the original title was "ADK router + domain skills + parallel sub-agents; per-request sessions; recorded model in tests". The original decision:
>
> One ADK root agent (router) loads domain skills on demand; cross-domain questions fan out via `ParallelAgent` with `output_key`s merged by a `SequentialAgent` step. Sessions use **`InMemorySessionService` per request** (watchers and asks are one-shot; conversation history for asks is persisted through core as `intel.answer`). A trace plugin implements every callback. Tests and W1–W3 gates use `RecordedLlm` (an ADK `BaseLlm` subclass replaying committed fixtures) selected by `MUNIM_MODEL_MODE`. Version pins (`google-adk 2.11.x`) are confirmed by the live probe before STACK is written.

**Why it changed.** The evidence comes from the **installed `google-adk==2.11.0` wheel**, read during the ADR-014 review. Each item is FACT:
- `ParallelAgent` is `@deprecated` "in favor of Workflow" (`.venv/…/google/adk/agents/parallel_agent.py:246`). The same message says "Workflow cannot yet be used as an LlmAgent sub-agent".
- Its own docstring says "**Session state is shared by every branch**", and a branch "sees the events that led to the fan-out" (`:259–262`). That refutes the old belief that branches do not share state (04 §2 cited R4 §C). Shared state would also let a branch that read untrusted text hand its prose to the orchestrator unmarked (review B1, taint laundering).
- `BaseAgent` is now `class BaseAgent(BaseNode, abc.ABC)` (`agents/base_agent.py:99`), and the graph engine bypasses a custom `_run_async_impl` (R6b).
- `BasePlugin` has **14** callbacks (`plugins/base_plugin.py`), not 7.

The founder also decided F5 (≤ 4 read-only branches for `investigate`) and F8 (the orchestrator is the "Manager"; skills belong to 8 named specialists).

**What this improves:**
- **Safety:** a branch cannot inherit or overwrite another context's state, and taint is one per-run flag that a branch report propagates (gated in T-042 and T-053).
- **Precision:** each branch starts from a ≤ 1k brief plus the shared prefix, with no orchestrator turns. That is the clean context R6a recommends.
- **Cost:** per-branch budgets are explicit (ADR-014 §3.4) and fan-out is disabled at the soft cap.
- **Testability:** each branch's first `LlmRequest` can be asserted, and all 14 callbacks have fired-tests.
- **Stability:** no dependence on a deprecated class, or on `BaseAgent` subclassing, which ADK 2.x already broke.

**Decision (current).**
- **The Manager.** One `LlmAgent`, presented as the Manager, is built per request with the constant name `munim`. The constant name keeps the system prefix identical across tenants, because ADK prepends the agent name: FACT, `flows/llm_flows/prompt/_identity.py:41`.
- **Skills.** The Manager loads specialist skills through `load_skill` and a `PackToolset`; toolsets are re-resolved on every step. An `@Specialist` address forces that specialist's skill.
- **Fan-out.** An `investigate` intent runs `fan_out`: `asyncio.gather` over ≤ 4 **branch `Runner`s**, each with its own `InMemorySessionService` session, named `munim_branch`. Branches share only the per-run `RunState` (budget, taint, handle table, trace buffer) and the plugin. They are read-only (no `propose_*`, `request_quotes`, `load_skill` or `fan_out`) and return a `BranchReport{tainted}`. Only the Manager calls `submit_answer`.
- **Not used:** `ParallelAgent`, `SequentialAgent`, custom `BaseAgent` subclasses, `MemoryService`, `DatabaseSessionService`, `SkillToolset` and `[eval]`.
- **Sessions** stay **`InMemorySessionService` per request** (gotcha 25). Thread history is never an ADK session: core supplies a bounded thread excerpt through the run-frame (F9).
- **The plugin.** One `MunimPlugin(BasePlugin)` implements all 14 callbacks and flushes traces in `on_run_error_callback` and in the runner's `finally`.
- **Gates** use `RecordedLlm`, selected by `MUNIM_MODEL_MODE`. `google-adk==2.11.0` is pinned (T-041, 7f6418a).

**Consequences.**
- Misspelled callback hooks are silent (R4 K14), so each of the 14 has a red-proven "fired" test (T-042).
- There is no ADK database, so no extra connections.
- Revisit `AgentTool` (`tools/agent_tool.py:133–279`, which runs a sub-`Runner` and inherits plugins) or ADK Workflow only if they can be used as an `LlmAgent` sub-agent with isolated state **and** they beat explicit per-branch budgets on a T-070 measurement.
