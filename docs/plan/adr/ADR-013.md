# ADR-013 · The book guard

**Status:** accepted (9 Oct 2026; revised after pass-1 review) · **Ledger:** R15, R26, R27, R28, R29, R25

**Context.** Grants alone cannot keep services from writing books: core-api's internal routes and the worker would otherwise hold the same rights as member routes (pass-1 review).

**Decision.** Every `core` table is tagged `munim:book` or `munim:operational`. A trigger `core.guard_book_write()` on every book table admits a change only for (1) a person's own command allowed by `core.command_authority`, (2) execution of an approved decision (`app.decision_id`), or (3) an allow-listed deterministic derivation (`app.posting_rule`) of a row that passed (1) or (2). Internal routes and jobs connect as `munim_svc`, which has no book-table grants (a service write fails with `42501` before the trigger). Draft and import execution happen on the member's `/v1/drafts/{id}:approve` request, already in the `munim_core` pool, with the draft set to `executing` under the current txid — a decision id cannot be replayed. Derivation rules live in the seeded `core.derivation_rule` table; book rows carry an `origin` column stamped by the trigger.

**Consequences.** Gates (M2 owns the DB ones, T-006 the route ones): every `core` table has a tag; `munim_svc` has 0 book privileges; as `munim_core` with no admitting context every book write raises `MB001`; replayed decision → `MB001`; a planted internal route writing `core.price` fails with `42501`; a member's own refund within authority succeeds (accept pair).
