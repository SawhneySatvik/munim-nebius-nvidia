## Env (apps/web)
| var | where | meaning |
|---|---|---|
| `NEXT_PUBLIC_MUNIM_API` | build | `/api` in production (same origin); `/mock` in dev/tests |
| `MUNIM_API_ORIGIN` | server | rewrite target for `/api/:path*` → `${MUNIM_API_ORIGIN}/:path*` (e.g. the munim-api URL; locally http://127.0.0.1:8790). Unset → no rewrite. |
| `NEXT_PUBLIC_MUNIM_STOREFRONT_KEY` | build | Cobnut's storefront key (public by design; printed by the world seed into `.run/`, never logged) |
| `MUNIM_MOCK` | server | `1` enables `/mock/v1/*`; otherwise those routes answer 404. Production never sets it. |
| `NEXT_PUBLIC_MUNIM_MOCK_CONTROLS` | build | `1` only with the mock |
| `MUNIM_DEMO_SIGNIN` | server | `1` enables the demo picker's server sign-in route |
| `MUNIM_DEMO_PASSWORD` | server secret | the one password of the four demo accounts (generated by the seed into `.run/`, git-ignored) |
| `SUPABASE_PROJECT_URL`, `SUPABASE_PUBLISHABLE_KEY` | server | for the demo sign-in route's password grant |
| `MUNIM_DEMO_TENANT_ID` | server | the tenant the picker signs into (changing it = "reseed on demand") |

Demo sign-in route (apps/web, server only): `POST /staff/demo-session {person: "owner"|"manager"|"counter"|"kitchen"}`
→ password grant at Supabase Auth for `<key>@cobnut-demo.invalid` with `MUNIM_DEMO_PASSWORD` → returns
`{token, tenant_id}` to the browser (the session module stores it as it stores a mock token today, then calls
`GET /v1/me`). Refuses anything but the four keys; 404 when `MUNIM_DEMO_SIGNIN` is unset. Never logs the token.
Locally with `MUNIM_IDP=local`, the same route may instead read tokens minted into a run-dir file (`MUNIM_DEMO_TOKENS`
= path), so the local gate needs no Supabase.
