## How the idea evolved
1. Sweep of all six themes (excluding BFSI), ranked by odds of selection.
2. User combined three: document-review swarm (#4) + voice-first micro-merchant (#6) + A2A buyer
   negotiating with supplier agents (#7) → a procurement loop.
3. A friend's freelancer-built ordering site (private repo; **read for context only, nothing taken**)
   shifted the idea from a voice request to a **data-first** start: orders → forecast → purchasing.
4. User generalised: an operations service and advanced analytics for small businesses, food first,
   with a deterministic POS/operations core and agents on top.
5. Market check (03-landscape.md) showed a crowded category with an obvious A2A codelab → emphasis on
   the review gate, multi-outlet pooled purchasing and the complete system.

## Stories considered for the demo
Monday-morning brief · hidden margin leak · month-end close — **all three kept** (D-012).

## Process lessons from the discussion session
- The user does **not** want ideas locked before they say so.
- The user picks the widest scope; lead with it, name the risk once, then build it.
- The user dislikes generic, crowded picks.
- The user answers multiple-choice questions with free-text additions; read them carefully.
